# 视频字幕布局与验证

[English](PLAYER_LAYOUT.md) | 中文

Issue #17 在右侧字幕布局基础上增加底部字幕。既有 `landscape-video` 类仍为所有展开的视频播放器选择沉浸式控件；实际视口方向通过 `matchMedia('(orientation: landscape)')` 选择字幕偏好。

## 模式与持久化

横屏依次切换 **右侧 → 底部 → 关闭 → 右侧**，默认右侧。竖屏依次切换 **底部 → 关闭 → 底部**，默认底部。字幕按钮在英语、简体中文及波斯语中均表示下一次操作。localStorage 的 `lumen.lyricModes` 分别保存两个方向的选择，与 `lumen.playerButtons`、媒体 IndexedDB 及音频字幕可见性独立。切歌、关闭重开播放器和应用重载后保留选择。窄屏选择右侧模式时，仅按宽度规则隐藏字幕，不改写偏好。

## 右侧模式

命名 CSS 容器为 `.player-sheet` 内容区。内容宽度达到 **656 CSS px** 时显示物理右侧独立歌词区；不足时隐藏并将空间还给视频。内容宽度不包含内边距、安全区和边框。侧栏保持 `clamp(180px, 25cqw, 280px)` 与 16px 间距，位于正常 flex 文档流中，RTL 也保持物理右侧。控件及渐变共用视频与侧栏边界；没有歌词时释放侧栏空间。

右侧及音频模式继续显示整份歌词，支持滚动和当前句自动居中。音频歌词显示行为不变。

## 底部模式

两个方向共用一个绝对定位的字幕区域，直接位于播放器下，独立于会裁切内容的视频行。右侧／音频模式将原歌词 DOM 放回视频行；底部模式不使用平滑滚动。横屏字幕以播放器容器底部为基准，仅预留系统底部安全区。竖屏优先将自然高度的字幕紧接实际 contain 画面下沿排列，前提是能完整放在进度／时间／播放控件之前；放不下时，以控件区域上沿为字幕下限，向上覆盖视频，不优先覆盖播放栏。叠放层级依次为视频、字幕、控制条、菜单；发生重叠时控件仍位于字幕上层。水平安全区变量与控件共用，字幕不接收指针事件，菜单位于控件之上。竖屏在控件自动隐藏时仍使用其布局边界，避免仅因控件显隐而跳动。字幕可以位于留白中，也可以覆盖视频；不参与视频 flex 尺寸分配，因此 **底部与关闭模式的视频尺寸完全相同**，视频始终使用 `object-fit: contain`。

保留整份歌词 DOM、既有 `findActiveLine`、下一句有效同步歌词判断及 Enhanced LRC 逐字状态逻辑。CSS 仅显示当前句和下一句，缺少当前句或下一句时保留一行空白。间奏的定时空行保留原有时间及下一句预览。底部模式重置滚动且不执行自动居中。没有歌词或只有非同步歌词时不显示底部区域；保留既有歌词内容及无歌词反馈 DOM。

空间判断使用视频宿主矩形和视频原始尺寸，计算居中 contain 后的实际画面边界。自然换行后的字幕可以完全放在画面下方时，允许使用该留白；否则可见区域最多为两行文字高度，超出部分直接裁切。行高读取正在显示的当前句／下一句，不再读取整份歌词中被隐藏的第一行：iPhone 诊断曾显示隐藏行为 18px／27px，而可见行为 24px／36px，导致需要 72px 的两句被限制为 54px。底部单独设置 `-webkit-text-size-adjust: 100%` 和 `text-size-adjust: 100%`，保持约定字号，不改变右侧／音频文字。元数据加载、宿主或字幕尺寸变化、方向变化、字体加载及歌词 DOM／状态变化都会触发重算，不计算文本长度。

所有模式保持 **18px／字重 600**；右侧和音频歌词行高仍为 **1.85**，底部模式按用户要求缩小为 **1.5**（通常每行 27px、两行上限 54px，实际裁切上限依据可见行的计算行高）。各模式保留当前句、下一句、已唱句及逐字高亮颜色，以及 `white-space: pre-wrap`、`overflow-wrap: anywhere`。底部布局移除歌词行内边距，让两行限制对应文字行高。长当前句可以占满区域并裁切下一句，不缩小字体，不添加省略号。

## 自动化覆盖

在仓库根目录运行：

```powershell
node --test tests/lrc.test.mjs
$testFiles = (Get-ChildItem tests/*.test.mjs).FullName
node --experimental-vm-modules --test $testFiles
node tests/browser-runner.mjs
node tests/browser-runner.mjs --video
```

Node 测试覆盖模式循环、独立持久化、无效偏好、播放／暂停／定位／切歌、过期异步结果、间奏、无下一句及 Enhanced LRC。底部模式检查禁止居中，右侧及音频仍保留居中。

桌面 Chromium 使用隔离配置、静音输出、实际本地录制的横向与竖向视频以及页面重载。检查模式与下一操作文案、方向恢复、底部／关闭矩形一致、从已滚动整首歌词侧栏切换后的文字实际可见性及播放中控件隐藏后的可见性、contain 重叠与不重叠、自然换行和裁切、RTL、多语言、模拟不对称水平及底部安全区、控件／更多菜单和按钮可见性偏好。右侧回归保留明确的 655／656／657 CSS px 内容宽度及 clamp 宽度检查。综合浏览器测试保留音频、伴奏、歌词、导入／备份及离线缓存检查。无需新增运行时模块或缓存命名空间；修改的运行时文件均已在 network-first 应用外壳缓存清单中。

## 待人工实机验收——未验证

- iPhone Safari 及 HTTPS 安装 PWA：两种方向的模式循环、旋转恢复、反复展开／收起、重启持久化、触摸定位、安全区、换行、歌词同步及控件／菜单访问。
- iPad Safari／PWA：横竖屏、分屏及播放／暂停时跨越 656px 边界，确认阈值下隐藏侧栏但保留右侧选择。
- 实际 AirPlay **屏幕镜像**：横竖屏进入／退出／重复连接、接收端实际画面、底部／右侧字幕可读性、可听输出及持续同步。
- 真实安全区与安装后 PWA 生命周期仍待人工验证。桌面模拟安全区及播放时间推进不能证明 iPhone 或 AirPlay 可靠性。本次不增加原生全屏、远程控制或电视独立显示。
