# 播放器宽度布局与验证

[English](PLAYER_LAYOUT.md) | 简体中文

基于已合并的 #7 布局，PR #9 按本轮要求进一步采用视频优先的区域分配。视频布局仍只有左右分栏或隐藏歌词两种模式，不按设备、UA、屏幕分辨率或横竖屏决定。

## 唯一视频宽度阈值

CSS 查询播放器 `.player-sheet` 的内容区宽度，**达到 784 CSS px** 时显示右侧独立歌词区；低于该值隐藏整个歌词区，视频恢复全部可用宽度。内容区宽度已扣除左右 padding、安全区域和边框，因此这不是视口宽度断点。

视频至少占可用内容宽度的 75%，间隔固定 16px，歌词宽度为 `min(300px, 25cqw - 16px)`。满足最小歌词宽度 180px 的条件为 `0.25 × W − 16 ≥ 180`，因此 W 至少为 784px。cqw 在子元素消费时相对播放器内容区解析；测试直接检查实际宽度，避免误用视口或其他容器。安全区域通过共用变量同时约束视觉区域和控件。歌词处于正常水平 flex 流中，RTL UI 也位于物理右侧。视频保持 `object-fit: contain`；进度、播放控件、菜单及渐变止于视频区，不侵入歌词区。字幕关闭或无歌词时也归还区域。

| 可用内容宽度 | 歌词 | 间隔 | 视频 |
|---|---:|---:|---:|
| 700px | 隐藏 | 0 | 700px |
| 780px | 隐藏 | 0 | 780px |
| 784px | 180px | 16px | 588px |
| 900px | 209px | 16px | 675px |
| 1100px | 259px | 16px | 825px |
| 1400px | 300px | 16px | 1084px |

所有歌词行均为 18px、600 字重、1.85 行高、无 transform。当前行、下一行和已唱行只使用颜色区分，保留 Enhanced LRC 逐字颜色和当前词标记。允许自然换行；没有按宽度、状态或全屏缩放字号的规则。

## 全屏边界

合入 main 的 #7 确定了上述宽度和排版规则；#6／PR #9 在此基础上删除了旋转回退。原生全屏保留当前方向，失败时使用直立页面铺满；只有用户明确选择横屏时才在适当原生上下文尝试锁定。所有模式只按实际内容宽度决定布局。旧 `landscape-video` 类名只用于视频控件样式，不作为方向判断。详见[全屏与方向](VIDEO_FULLSCREEN.zh-CN.md)。

## 自动化检查

`tests/video.browser.html` 检查实际 computed styles 和 bounding boxes：390×844、568×320、844×390、768×1024、820×1180、1024×768、1280×800；还在相反方向的视口中固定内容区为 700／780／783／784／785／900／1100／1400px，并使用非对称 40／44px 安全区域变量。检查表中精确区域宽度、至少 75% 视频、180–300px 歌词、16px 间隔、相同宽度的一致结果、无重叠／堆叠、RTL、控件边界、固定排版、自然换行、逐字颜色及直立页面铺满。原生状态和方向锁定结果使用明确标记的 API 模拟。浏览器检查使用打包后的不可变资源，Node 保留 LRC／Enhanced LRC 同步等回归覆盖。

这些是桌面检查，不能证明 iOS Safari、安装后 PWA、实际声音或 AirPlay 行为。

## 真机验收——全部待验证

- iPad Safari 与安装后 PWA：横竖屏、分屏、784px 附近调整宽度，暂停和播放时切换。确认足够宽时右侧分栏，不足时隐藏，视频不变形。
- iPhone Safari：竖屏窄宽度隐藏歌词；横屏按实际内容宽度判断。检查刘海／安全区域、字幕开关、更多／队列、触摸定位和 18px 多语言歌词。
- 重复进入／退出原生全屏及直立页面铺满，检查布局和字号；测试显式横屏请求、失败、跟随设备及手动旋转，确认没有 CSS 旋转。
- 真正连接 AirPlay 屏幕镜像，分别从横竖屏进入／退出并重复，观察外接屏幕方向、歌词及实际声音；桌面结果不能替代这些检查。使用 HTTPS 做完整 PWA 验收，HTTP LAN 仅适合基础视觉测试。
