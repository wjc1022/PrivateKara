# 播放器宽度布局与验证

[English](PLAYER_LAYOUT.md) | 简体中文

对应 Issue #7、Draft PR #8。本轮用户明确要求替代 Issue 原先允许窄屏叠加的方案：视频布局只有左右分栏或隐藏歌词两种模式，不按设备、UA、屏幕分辨率或横竖屏决定。

## 唯一视频宽度阈值

CSS 查询播放器 `.player-sheet` 的内容区宽度，**达到 656 CSS px** 时显示右侧独立歌词区；低于该值隐藏整个歌词区，视频恢复全部可用宽度。内容区宽度已扣除左右 padding、安全区域和边框，因此这不是视口宽度断点。

**656 CSS px 阈值保持固定**，与歌词宽度规则独立。达到阈值且存在歌词、字幕开启时，歌词优先占用 `clamp(180px, 25cqw, 280px)`，扣除 16px 间隔后的剩余空间分配给视频。低于阈值、字幕关闭或无歌词时，视频使用全部可用宽度。安全区域通过共用变量同时约束视觉区域和控件。歌词处于正常水平 flex 流中，UI 为 RTL 时也位于物理右侧。视频保持 `object-fit: contain`；进度、播放控件、菜单及底部渐变的右边界与视频区一致，不侵入歌词区。

所有歌词行均为 18px、600 字重、1.85 行高、无 transform。当前行、下一行和已唱行只使用颜色区分，保留 Enhanced LRC 逐字颜色和当前词标记。允许自然换行；没有按宽度、状态或全屏缩放字号的规则。

## 沉浸式播放边界

Issue #13 移除全屏按钮及其原生全屏请求、方向锁定、页面铺满状态和 CSS 旋转回退。视频播放器仍覆盖目录；`landscape-video` 类名用于所有展开视频的沉浸式控件样式，不作为方向判断。保留横竖屏响应式布局、656px 内容区阈值及控制按钮自动隐藏和交互唤出。应用不控制系统或 AirPlay 接收端方向。

## 自动化检查

`tests/video.browser.html` 检查实际 computed styles 和 bounding boxes：390×844、568×320、844×390、768×1024、820×1180、1024×768、1280×800；还在相反方向的视口中固定内容区为 655／656／657／720／760／1120／1200px，并使用非对称 40／44px 安全区域变量。检查相同可用宽度的一致结果、阈值两侧、歌词 clamp 精确宽度及视频剩余宽度、无重叠／堆叠、RTL 物理右侧、控件边界、固定排版、自然换行、逐字颜色、指针定位、沉浸式控件及旧按钮设置兼容。基础浏览器检查覆盖音频歌词的深浅主题固定排版和离线资源更新；Node 检查保留 LRC／Enhanced LRC 同步等回归覆盖。

这些是桌面检查，不能证明 iOS Safari、安装后 PWA、实际声音或 AirPlay 行为。

## 真机验收——全部待验证

- iPad Safari 与安装后 PWA：横竖屏、分屏、656px 附近调整宽度，暂停和播放时切换。确认足够宽时右侧分栏，不足时隐藏，视频不变形。
- iPhone Safari：竖屏窄宽度隐藏歌词；横屏按实际内容宽度判断。检查刘海／安全区域、字幕开关、更多／队列、触摸定位和 18px 多语言歌词。
- 反复展开／收起播放器并旋转设备，检查目录覆盖、布局、字号及控制按钮隐藏和唤出。
- 真正连接 AirPlay 屏幕镜像，分别从横竖屏进入／退出并重复，观察外接屏幕方向、歌词及实际声音；桌面结果不能替代这些检查。使用 HTTPS 做完整 PWA 验收，HTTP LAN 仅适合基础视觉测试。
