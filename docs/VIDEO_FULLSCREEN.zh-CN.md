# 视频全屏与方向

[English](VIDEO_FULLSCREEN.md) | 简体中文

对应 #6，依赖 #7 的容器响应式布局。播放器先请求 **HTML 容器全屏**，再尝试 `screen.orientation.lock('landscape')`。以 `document.fullscreenElement` 确认原生全屏；请求 Promise 成功不等于已经进入。API 缺失或拒绝时保留直立的页面铺满和响应式布局，按钮明确显示“退出页面铺满”。页面铺满无法隐藏浏览器工具栏。

全屏与方向锁定分别记录结果。方向锁定不可用或失败时，持续显示本地化提示，包含 iOS 控制中心方向锁定、手动横放及检查 AirPlay 外接屏幕的步骤。iOS 检测只选择提示，实际行为由能力检测和请求结果决定。应用不再通过 CSS 旋转界面，也不会进入丢失 HTML 歌词的原生视频全屏。应用无法检测或控制 AirPlay 接收端方向，锁定成功也不能证明镜像正确。manifest 改为 `orientation: any`，不再要求安装的应用固定竖屏；系统仍可能限制方向，安装模式保持竖屏时可尝试 Safari。

关闭、切歌（包括视频切视频）、原生全屏退出、导航、页面离开及进入后台均取消待完成请求并释放方向锁定。进入／退出请求串行处理，迟到的结果不能恢复旧状态或解除下一次会话的锁定。浏览器拒绝退出时保留实际原生全屏状态，可再次退出或使用浏览器退出控件。所有模式使用水平触摸定位，视频保持 `object-fit: contain`。

## 证据边界

Node 控制器测试模拟原生 API，覆盖成功、缺失、拒绝、同步异常、原生退出、重复进入、异步结果迟到、取消、退出失败及进入／退出串行处理。Chromium 检查真实页面铺满几何、水平触摸定位、提示、生命周期清理及 #7 的响应式布局；基础检查包含新增模块的离线缓存。模拟成功和桌面浏览器均不能证明移动端原生旋转或 AirPlay 可用。浏览器输出静音，不能证明实际声音输出。

平台资料（并非设备验证）：[WebKit Safari 16.4](https://webkit.org/blog/13966/webkit-features-in-safari-16-4/) 描述 macOS／iPadOS 容器全屏及初步方向 API，不能据此推断所有 iPhone 均支持；[方向锁定文档](https://developer.mozilla.org/en-US/docs/Web/API/ScreenOrientation/lock) 标注支持有限，并说明可能要求移动端全屏，因此必须处理能力缺失和请求失败。

## 实机检查清单——全部待验证

每项记录设备型号、系统版本、Safari／安装模式、方向锁定设置、接收器／电视型号及提交版本。使用 HTTPS，保留原始媒体和备份，分别准备含逐字 LRC 和无歌词的 MV。

1. **iPad Safari 与安装后 PWA：**分别从横屏和竖屏进入；按钮和浏览器控件退出；重复三次。暂停／播放时旋转、调整分屏宽度。检查右侧歌词、视频比例、安全区域、更多／队列、提示可读性及水平触摸定位。
2. **真实 iPhone Safari + AirPlay 屏幕镜像：**通过控制中心启动屏幕镜像（区别于仅视频 AirPlay）。分别开启／关闭竖排方向锁定，从竖屏进入全屏；记录原生横屏是否成功，或是否显示直立铺满与提示。观察真实外接屏幕中的视频、控件、歌词是否正向。自动锁定受限时按提示关闭方向锁定并横放手机，再检查外接屏幕；应用无法强制接收端旋转。
3. 从横屏进入、退出、回到竖屏、重复进入至少三次。确认没有侧转界面、残留锁定或无法操作的控件。在手机与外接屏幕检查 25%／75% 触摸定位、字幕开关及歌词同步。
4. 铺满时切换 MV、切到音频、关闭／重开、导航、进入后台／返回、断开／重新连接镜像。确认状态清理及后台播放返回后需手动恢复。安装后 PWA 重复测试；方向仍受限时尝试 Safari，并记录差异。
5. 单独检查实际可听输出、接收端延迟及持续播放。桌面通过、时间推进、API Promise 成功都不能替代这些结果。外接屏幕仍侧转属于实机检查失败，需继续调查，不能算作回退成功。
