# 应用版本与手动发布

[English](BUILD_IDENTIFICATION.md) | 简体中文

只维护 `version.json`：三段数字的应用版本、正整数 build，以及可选的发布日期和更新记录。每次发布必须递增 build，包括应用版本不变的发布；不要在代码中重复维护。

直接静态托管仓库文件，无需打包或 dist：

```sh
python -m http.server 8080
```

手机／PWA 验收需要 HTTPS；HTTP 局域网仅支持基础布局检查，不支持 Service Worker。本地证书安装需要另行授权，设备也需手动信任。

## 显示与更新

启动时 versionService 仅读取一次普通 version.json，冻结本页面的版本／build。已有 Worker 时读取其应用壳缓存，离线时亦然。“关于”显示这份信息，导航使用同一版本。服务器最新版本通过另一条带时间戳、仅访问网络的请求检查，不会重标记当前页面。首次尚未受控的加载依赖已部署文件。

Worker 注册 URL 包含 build，仅修改 build 也会触发安装，无需另改 sw.js。缓存名称为 lumen-shell-build-N。安装要求静态清单完整、版本文件 build 匹配。已有客户端在用户接受更新前继续使用旧 Worker；接受后注册新 build、发送 SKIP_WAITING，等待 controllerchange 再刷新。失败或超时保留当前页面。离线重开保留已安装版本。激活仅清理旧 lumen-shell- 应用缓存，不改动其他缓存、IndexedDB 或已导入歌曲。

## 发布步骤与限制

1. 修改 version.json 并递增 build，完整部署应用文件。不要发布不完整版本；本方案不校验资源哈希，也不保证部署原子性。
2. 在已有媒体库中检查关于／页脚、更新发现、接受后的激活刷新，以及离线重开，无需重置数据。
3. 忘记递增 build 可能导致更新无法发现、同一缓存标识对应内容被替换，这是手动发布的已知限制。应用版本变化也不能重置 build。
4. 已打开页面的显示值在刷新前保持不变；其他标签页激活更新后，应刷新旧页再验收。普通静态托管不保证资源不可变或多标签页源码溯源。
5. 较早的实验性不可变发布，应在部署后从仓库入口重新打开；本修正不保证所有旧实验标签页自动迁移。

桌面自动测试使用隔离浏览器配置、模拟发布和合成媒体。iPhone／iPad Safari 与独立 PWA 的离线重启持久性、实际声音、全屏方向及 AirPlay 屏幕镜像仍须真机验证，桌面模拟不能证明这些行为。
