# 构建识别与发布

[English](BUILD_IDENTIFICATION.md) | 简体中文

## iPhone 上如何确认当前构建

使用打包后的站点，打开菜单 → 关于，记录“当前运行的应用版本”“当前运行的构建标识”和“不可变源码快照”。这些值来自本次已加载的 JavaScript 模块，不从服务器最新 version.json 推断。点击“检查服务器构建”仅更新另一行服务器信息，不改变当前运行标识。接受更新并重新加载后，当前标识才变化；离线重开仍显示缓存构建。

Git SHA 只表示打包时检出的来源。只有输入与该提交逐字节一致且工作区干净时才标为干净检出；修改、未跟踪或被忽略的生成资源均不能冒充该提交的精确构建。实际身份始终由完整内容快照和构建标识确定。原始源码预览明确显示“未验证”，不能用于确认 iPhone 验收版本。

## 唯一元数据来源与静态输出

维护者只编辑 version.json 中的应用版本、发布日期和更新说明，不手动维护 build 数字、导航版本或缓存版本。无依赖的 Node 脚本读取这些配置及实际运行输入，生成：

- sourceRevision：运行输入、文件路径及生成器的 SHA-256 快照；包含独立生成资源的实际字节。
- build：配置、内容快照和 Git 来源记录的 SHA-256 标识；运行资产改变后，即使应用版本未变，也会产生新构建。
- builds/构建标识/：不可变的 JS、CSS、语言文件和资源；生成的 build-info.js 嵌入同一份运行元数据。
- 根目录 index.html、manifest.json、version.json 和 sw.js：入口绑定不可变资源目录；SW 缓存名称为 lumen-shell-构建标识，并验证每个预缓存响应的 SHA-256。

根 version.json 表示服务器当前提供的发布包。运行界面从已加载模块获取身份，更新器只以带查询参数、禁止缓存的网络请求获取服务器元数据。相同版本号的新构建也可触发更新，“稍后”按构建而非仅按版本记忆。

## 本地验收与未来更新流程

```powershell
node scripts/prepare-build.mjs
py -3 -m http.server 8081 --bind 0.0.0.0 --directory dist
```

使用独立测试端口可避免与先前源码预览的 origin 混淆；不要清除现有媒体库或浏览器数据。HTTP LAN 可识别静态包并测试基本布局，但完整 PWA／Service Worker 验收仍需要可信 HTTPS 或 Windows 本机 localhost。iPhone／iPad 证书信任和 AirPlay 仍需实机确认。

1. 完成代码、测试和逻辑提交，更新 version.json 的版本／说明（每次资产变化不必人为增加 build 数字）。
2. 在干净检出运行上述打包命令，记录输出的完整 build、sourceRevision 和 Git 状态。导出源码无 Git 时仍有内容标识，Git 来源显示未知。
3. 仅部署完整 dist 输出。先上传不可变 builds 目录，再更新根元数据／入口，最后更新 sw.js；保留旧资源目录，供旧标签页使用。不要事后修改生成文件或覆盖同一构建目录。
4. iPhone 关于页先记录当前身份，再检查服务器身份；通过正常更新流程激活并重新加载，确认新身份。还需测试离线重开、媒体持久化及实际播放。

仓库当前没有可用的 .github/workflows 部署配置；本任务未修改远程托管设置或发布网站。现有托管若直接发布仓库根目录，必须改为发布打包产物，否则只能得到未验证源码预览，不能依赖新离线功能。简单本地源码预览仍可直接运行静态服务器，但不会注册 SW，也不会声称具有发布构建身份。

## 更新生命周期和限制

安装时先验证整个资源集合；任何缺失／哈希不符都会拒绝新 worker，旧完整构建继续可用。安装完成后等待用户选择更新，不强制打断当前播放器。已在 waiting 状态的 worker 会立即收到激活请求；超时／失败不盲目重新加载。更换 controller 本身不会给已加载模块改名，只有页面重新加载才切换当前构建。

旧不可变缓存保留，避免其他尚未重载的标签页混入新模块；不会删除无关 Cache Storage、IndexedDB 或媒体。代价是历史缓存／发布目录会占用存储：未来可增加经活跃客户端确认的安全回收，本任务不自动清理。首次未受 SW 控制的访问依赖发布端保持不可变目录完整；缺失资源可能导致加载失败。内容标识和完整性校验不能替代 HTTPS，也不能证明 iOS 或 AirPlay 行为。

自动化覆盖：打包确定性与输入变化、Git／生成输入来源、运行与服务器版本区分、同版本构建更新、waiting 激活、损坏发布拒绝、离线重载及既有库持久化。桌面检查不等于 iPhone 实机验收。
